# P/N 阈值数值回显设计

## 目标

用户按 P/N 调整阈值时，能在 Home Assistant 直接看到当前数值，不猜按键次数，不改变原始燃气计数、ADC 或版本字段含义。

## 已批准方案

- 固件普通 BTHome 广播增加标准 `0x3E count32`，值为当前阈值（20～2000，uint32 小端）。
- 当前广播 26 字节，新增 5 字节后正好 31 字节；版本对象 `0x53` 相应后移，广播构建必须统一使用布局常量。
- P/N 调整后请求在下一个 300 ms 采样周期补发一次广播；松手保存后再请求一次，确保最终持久化值回显。
- 平时保持 60 秒广播周期，只有调整时增加广播。
- HA 解析 `0x3E` 为 `threshold`，新增中文只读实体 `当前采样阈值（P/N 按键调整）`。
- 原生 BTHome 可能出现通用 Count 实体，这是使用标准字段的已知副作用。
- 固件升级为 1.4.9，HA 升级为 0.7.4；OTA 协议继续为 8，不修改 CRC 或 IAP。
- 用户追加要求：设备页现有实体显示名同步中文化，包括固件版本、升级状态/进度、
  燃气三值、OTA 模式、检查/取消升级及阈值操作；unique_id、entity_id、属性键和服务保持不变。

## 备选方案

LED 闪烁只能提示按键活动，无法清楚表达 100、110、150 等绝对值，因此不采用。

## 验收

1. C 布局测试确认版本长度 5 时广播总长 31、AD length 27、阈值对象位于 19～23、版本对象位于 24。
2. 阈值 2000 编码为 `3E D0 07 00 00`；旧阈值与新阈值不同时触发补发，松手最终值也补发。
3. HA 对同一广播解析出 gas、version、threshold，并在中文传感器显示阈值。
4. 全量固件/HA 测试及 INT_SOFT、 mret 构建检查通过；实机按 P/N 后约 300 ms 内看到新值。
